# Kimi K3 真实时序文字 B-roll 设计

## 目标

根据原视频 `00:22.80–00:24.20` 的逐帧证据，生成一个 1280×720、30 FPS、42 帧的可编辑 Remotion B-roll。模板只保留 B-roll 本体，不包含作者水印、平台标识和底部口播字幕。

## 方案比较

### 方案 A：直接裁切原视频

视觉最接近，但文字、颜色、正文和节奏都不可修改，无法形成可复用模板。

### 方案 B：为本镜头编写专用 TSX

可以精细复刻，但会让每个新参考镜头都产生一套新代码，不利于素材库长期维护。

### 方案 C：继续使用 scene.json，并补充最小通用能力

把正文拆成逐行动画元素；主标题和高亮标题保持连续扫入关系。现有关键帧引擎已经支持遮罩、位移、模糊和透明度；只增加纵向独立缩放和可选 CSS 背景纹理字段，不新增第三方包。

采用方案 C。

## 画面结构

- 深蓝色纹理背景。
- 主标题前半句。
- 黄色高亮底纹。
- 高亮标题作为一个整体，与黄色底纹共享同一组横向揭示帧点。
- 一行低对比英文辅助文字。
- 五行正文，每行独立控制显隐、模糊和横向揭示。

## 时间线

- 第 0–17 帧：细线先出现；它不是独立划线，而是黄色高亮被压扁后的起始状态。
- 第 6–16 帧：主标题前半句从左向右揭示。
- 第 10–26 帧：黄色底纹从下向上贴入，并与高亮标题同步从左向右揭示；它们属于同一条连续运动链。
- 第 18–31 帧：英文辅助文字从左下方缓慢上浮并显现。
- 第 20–41 帧：正文五行从上到下错峰生成。
- 第 40–41 帧：完整画面短暂停留，镜头结束。

所有帧点均来自原片定点取帧后的观察；没有通过坐标跟踪计算的位移量仍标记为 `observed`，不写成精确测量。

## 数据流

```text
原视频定点取帧
  -> 真实时间线
  -> scene-reference-v7-synced.json
  -> 低噪运动检查
  -> scene-final-v7-synced.json
  -> Remotion 渲染
  -> 开始/中间/结束帧 + Contact Sheet
  -> 对照原片修正
```

## 验收标准

- 输出为 H.264、1280×720、30 FPS、42 帧。
- 不出现水印和底部口播字幕。
- 标题前半句、高亮底纹和高亮文字形成一条连续的从左向右节奏，不出现独立划线阶段。
- 黄色底纹从下向上贴入，并与所在文字区域同步横向扩展。
- 英文辅助文字同时具备从左出现和从下上浮的方向感。
- 正文从上到下逐行由虚变实。
- 最终一帧文字不溢出、没有意外换行。
- JSON 校验、TypeScript 检查和四张质检图片全部通过。

## 用户复核修正

第四版虽然按取帧顺序制作，但把细线、标题和高亮理解成了三个相继动作，导致真实的同步扫入节奏被拆散。用户明确指出主标题是从左到右，高亮同时从下向上贴入并从左向右展开，辅助文字从左下方上浮，正文逐行生成。

第五版先取消独立划线；逐帧并排复核后发现，原片确实存在细线，但它更像高亮底纹的压缩起始状态。第六版恢复细线并把它与高亮连成一个动作；第七版整体后移约 3–4 帧，使标题、高亮、辅助文字和正文的启动时间更接近原片。最终采用第七版。
