# 参考分析与质量循环

## 第一性问题

每次分析只回答这些问题：

1. 画布多大、视频多长？
2. 画面中真正独立的元素有哪些？
3. 每个元素在哪里、占多大、谁遮住谁？
4. 观众先看哪里，再看哪里？
5. 每个元素何时出现、如何移动、何时稳定或消失？
6. 哪些事实来自测量，哪些只是推断？

与这六个问题无关的细节不进入第一稿 JSON。

## 参考素材分析

### 图片

- 删除水印、平台标识和口播字幕。
- 整张虚化背景视为一个背景，不拆成大量小物体。
- 大段正文合并为一个正文块。
- 一起移动的内容优先放进顶层 `groups`，让父级关键帧控制整组运动；`groupId` 只保留语义归类。
- 视觉中心以一至两个为宜，特殊情况最多三个。

### 视频

- 先用 Contact Sheet 找阶段，不从第一帧逐张盲看。
- 检查背景是否静止、主体是否独立运动。
- 遮挡发生时不要把像素变化直接判断成位移。
- 文字需要区分整体进入、顺序进入和散入。
- 先判断动画层级：整组内容的父级运动与标题、高亮、辅助文字、正文的局部运动必须分开记录，不能把父级位移复制成多个互不相关的元素动画。
- 父级整组进场若应连续移动，优先只保留起点和终点的一次插值。不要在多个中间关键帧上重复使用 `out-cubic`，否则每一段都会重新减速，形成肉眼可见的停顿和再启动。
- 需要中间路径点时，先检查逐帧位移增量；除非参考画面明确存在顿挫，否则相邻帧速度不得在路径点附近突然接近零再增大。
- 一整行标题即使局部有高亮或颜色变化，也必须先判断颜色来自字符样式还是图层混合。差值混合造成的黑白变化不得拆成字符片段：整句只保留一个文字元素，活动色块另做一个形状元素。
- 正文需要区分“逐行显现”和“同一段落逐字生成”。逐字段落应保留首行缩进和自然换行，不拆成多条独立文字。
- 辅助文字出现时检查路径是否为直线；若中间帧显示横纵速度不同，应使用多段关键帧表达浅弧线。
- 线条需要区分擦除和整条淡入。
- 先判断多个可见变化是否属于同一条连续运动链。标题、高亮和引导状态若沿同一方向同步推进，不得仅因它们是不同元素就拆成三个先后阶段。
- 检查运动方向的两个轴：横向揭示与纵向贴入可能同时发生。例如高亮可以从左向右扩展，同时从下向上贴到文字底部。
- 辅助文字需要分别判断横向来源和纵向来源；“从左出现”和“从下上浮”可以同时成立。
- 一段素材包含多个剪切点时先拆段。

## 硬性质量门

以下全部通过才能交付：

- JSON 校验通过。
- MP4 存在且非空。
- `ffprobe` 能读取视频流。
- 输出画幅、帧率和时长与 JSON 一致。
- 开始、中间、结束帧没有意外黑屏或残留旧素材。
- 元素位置、比例、层级和遮挡符合参考意图。
- 元素出现顺序和主要运动符合参考或明确的默认设计。
- 低噪模式没有泄漏原参考中的具体品牌、水印和长文案。
- 最终模式中的文字可读，图片和视频没有明显拉伸。

## 软性质量门

- 视觉中心清楚。
- 动画节奏有先后，而不是所有元素同时出现。
- 没有无意义的小幅抖动。
- 运动不会让用户来不及阅读内容。
- 相同层级的元素具有一致视觉语言。

软性门未通过时允许继续循环，但每轮只修最主要的一项。

## Loop Engineering

```text
输入
 -> 写或改 scene.json
 -> 静态校验
 -> Remotion 渲染
 -> ffprobe 检查
 -> 看四张质检图
 -> 找最大问题
 -> 只改一个根因
 -> 再渲染
```

问题定位顺序：

1. 文件和 Schema 错误。
2. 画布、时长和帧率错误。
3. 元素缺失或 ID 错误。
4. 位置、比例、层级和遮挡错误。
5. 出现时间和运动方向错误。
6. 节奏、缓动和视觉风格问题。

先修上层根因，避免用动画参数掩盖布局错误。

## 迭代记录

每轮记录：

- 当前版本号。
- 最主要问题。
- 修改的 JSON 字段。
- 修改前后的关键帧。
- 本轮结论：通过、继续或阻塞。

默认最多四轮；同一问题连续三轮没有改善时停止并说明原因。
