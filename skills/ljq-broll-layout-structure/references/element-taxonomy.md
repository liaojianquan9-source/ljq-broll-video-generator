# 元素分类与属性表

拆元素、填写外观或解释蒙版时读取。分类用来减少重复判断，不是要求给每个元素添加全部效果。视觉修正的优先级由[静态视觉判断](static-compositing.md)维护。

## 两轴分类

先确定“对象是什么”，再判断“有哪些可见属性”。同一个ID可以同时带几何、外观和合成属性；效果变化归motion，稳定底值归layout。

| 对象 | 拆分口径 |
| --- | --- |
| 文字／数字／参数 | 可独立换字、定位、遮挡或运动的语义块；逐字时保留父文字ID并记录字符行为，不必为每个笔画建ID |
| 媒体 | 图片、透明贴图、实拍或视频；PNG只是文件格式，不等于已经抠好，也不等于素材完整 |
| 图形／容器 | 线条、图标、框、节点、背景装饰；线段独立运动时分ID，共同镜头保留父组 |
| 组／合成层 | 有共同变换、裁切或遮罩的内容；组不能吞掉需要替换的子元素ID |

## 共享属性

| 分类 | 有证据时记录的参数 | 核对要点 |
| --- | --- | --- |
| 几何 | 可见边界、容器框、锚点、位置、scaleX/Y、旋转、裁切、父组、zIndex | 区分等比与非等比缩放；位置注明画布/父组坐标系及对齐参照 |
| 变形 | 透视平面或四角关系、弯曲/扭曲方向与强度 | 旋转不等于透视；只有可见证据才实现，不因“不常用”而漏掉真实变形 |
| 填充与材质 | 纯色、渐变方向/色标、纹理来源与映射、明暗/高光 | 颜色、纹理、材质是不同概念；主题角色按参考，不把局部反光当新增主色 |
| 混合与透明 | 目标底层、候选混合模式、图层opacity、效果opacity | 正片叠底/滤色/叠加等是候选，不凭压平视频断言唯一模式 |
| 描边 | 颜色、透明度、宽度、内/中/外位置 | 主轮廓与阴影边缘分开；替换后描边必须来自新内容 |
| 阴影 | 颜色、opacity、模糊、扩张、距离与角度 | 距离/角度也可换算为dx/dy；记录坐标系与处理顺序 |
| 辉光 | 颜色、强度/opacity、扩张、模糊范围 | 沿每个字形/图像alpha发光，与背后的中心光团分开；后者可独立定位时建ID |

位置不要求用户填写坐标：用源画面测量主体中心、基线、边缘对齐、相邻距离和留白，再写百分比bounds与锚点。主体、容器、阴影/辉光的可见范围分别量。

## 文字专属

- 文案、字体族/字形来源、字重、字号、真实斜体或模拟倾斜、下划线。
- 字距、行距、换行、对齐、基线、字面宽高比和缩放后占位。
- 字体候选按中文、数字、拉丁与手写分别比较；Top 3证据和精确识别边界见[字体与可编辑边界](static-compositing.md#字体与可编辑边界)。
- “字体颜色”拆为可编辑填充、材质和效果。字内纹理不会让文字变成图片元素。

## 媒体专属

- 来源/许可、宽高比、有效内容或alpha边界、完整度、裁切来源、object-fit/position。
- 抠像/分割是否已经存在、边缘羽化与颜色污染；需要新增抠像且影响范围时单独确认，不把它设为本流程默认新增功能。
- 视频再记录源时间映射与静态观察帧；不要仅因格式扩展就自动进入完整视频处理。

## 蒙版是关系，不是另一种素材格式

每项写明内容提供者、遮罩提供者、父级/坐标系、alpha或亮度通道、反相，以及位置、旋转、尺寸、羽化。矩形适用时才有圆角；可选线性、圆形、矩形、live文字或自定义路径。将含糊的“选择”明确成“遮罩目标/通道/反相”，避免各模型自行解释。

记录实际处理链，例如“纹理定位 → live text遮罩 → 描边 → 阴影”。描边和阴影属于合成效果，不是每个蒙版必带的字段。沿字形辉光通常不需要角度；中心放射光才考虑光源位置与方向，不能只给一个笼统的‘字体发光位置’。

“文字里面可见月表纹理”是观察；“由几个月亮叠加产生”只是候选实现。选择能保持替换性且匹配结果的方法，不宣称恢复原始图层。

## 写入合同

用现有schema支持的bounds、appearance、asset、parentId、fontCandidates等字段。暂不支持的关系写到该元素evidence或案例内分析表并链接，不往JSON塞未经schema支持的字段。

每项记录：`elementId｜分类｜可替换/prop｜观察值或候选｜坐标/合成关系｜源帧证据｜置信度｜未决差异`。未知≠不适用；没有观察到的效果保持保守默认。完成标准是每个可独立替换/定位/遮挡/运动的对象有ID，适用属性和未决项都可追溯。
