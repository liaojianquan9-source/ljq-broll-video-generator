# 静态合成与字体判断

## 可分析与不可唯一确定

从压平视频可以观察或估计最终像素效果：透明度、颜色关系、模糊半径、阴影、发光、饱和度、对比度、色相、裁切边界和可能的混合模式。但无法仅凭结果唯一确定原软件、插件、精确参数或图层堆叠方式。

## 记录方法

- 直接像素/几何测量记 `measured`。
- 全分辨率帧可清楚观察但未数值拟合的记 `observed`。
- 多种实现都可能产生同一结果时记 `inferred`，在 evidence 中列候选。
- 为了可编辑性使用的保守值记 `default`。

先匹配最终视觉，再追求制作方法。`mixBlendMode`、`filter`、`opacity`、`blurPx`、亮度、对比度、饱和度、色相、阴影和遮罩都写入元素 `appearance`，不要藏在聊天说明里。

## 字体

不同视觉角色分别识别字体：中文标题、数字、单位、拉丁字母和手写标注不能默认共用一套字体。

1. 从清晰落定帧裁出字形，保留原始裁切；尽量用边缘或亮度分层减弱辉光、描边和背景纹理。
2. 枚举本机字体与项目可合法使用字体，用相同文案渲染候选。
3. 先调整字号、字重、字距、行高和基线，再在小范围内调整 `scaleX`。大幅水平压缩通常意味着候选错误。
4. 比较外轮廓、负空间、笔画端点、数字开口、衬线和字面比例，保存 Top 3 并排或叠放证据。
5. 记录字体名称、来源、许可、渲染参数和置信度；能合法打包时随案例保存字体文件，否则声明依赖。

找不到精确字体时使用轮廓最接近候选并记录已知差异。禁止用原片文字截图、alpha 贴片或模糊覆盖来伪装字体已经匹配。

## 静态材质拆层

文字字形确定后，再拆分字面渐变、顶部受光、描边、外发光、内阴影、厚度、纹理和高光扫层。持续存在的材质光与只在入场期间出现的模糊或残影分别记录，避免动效阶段把永久材质错误地收敛为零。

每个排版场景都要保存 source/render/compare 落定 still。几何和字体轮廓未通过前，不开始动效实现。

## 混合模式校准

在相同底图和颜色下，对少量候选模式做 still 对比。不要无边界遍历所有 CSS 模式。若差异主要来自素材本身或上游色彩管理，应把问题归回资产或实现，而不是反复调整混合模式。
